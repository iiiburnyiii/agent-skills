# Examples / Примеры

Good / bad patterns for the `obsidian-research-note` workflow.

The skill body in `SKILL.md` defines the rules; the files here show what those rules look like in practice and what failure looks like next to them. Each file pairs a Bad pattern with a Good pattern so the contrast is explicit.

| File | What it covers / Покрывает |
|---|---|
| `clarifying-questions.md` | The clarification round before a plan. Good = thorough materiality-based questioning; bad = one vague question or no questions at all. |
| `plan-good-vs-bad.md` | A full `## План ресерча` for the same topic, written twice: vague vs measurable, no vault links vs confirmed vault links, generic sources vs diverse categories. |
| `note-fragments-good-vs-bad.md` | Per-section fragments of a final note: `## Источники`, `## Что Выбрать`, `## Сравнение`, wikilinks/candidates, `## Расхождения В Источниках`. |

## How to read the examples / Как читать

- **Bad** comes first, **Good** second. The contrast matters more than either example in isolation.
- Comments under each block name the specific rule from `SKILL.md` that the example honours or breaks (`Source Policy → diversity`, `Plan Format → materiality bar`, etc.).
- Examples use a recurring topic — compact e-readers in 2026 — so the same scenario can be followed across files. The topic is illustrative; the patterns apply to any research note.
- Code fences with `markdown` are literal note/plan content. Surrounding prose is meta-commentary, not part of the artifact.

## When to consult which file / Когда что читать

- Drafting the clarification round → `clarifying-questions.md`.
- Drafting the plan → `plan-good-vs-bad.md`.
- Writing the final note → `note-fragments-good-vs-bad.md`.
- Before finishing → skim all three to sanity-check the result against the bad patterns.
